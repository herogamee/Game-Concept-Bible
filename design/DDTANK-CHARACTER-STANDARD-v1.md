# มาตรฐานตัวละครแบบ DDTank — ฐานงาน v1

สถานะ: **ล็อกฐานงานตามคำสั่งเจ้าของ 2026-10-07** เพื่อพัฒนาต่อโดยไม่กลับไปเปลี่ยนโครง/พิกัดโดยพลการ งานปัจจุบันคือแลปตัวละคร แยกจากเกมหลักและการเลือก production engine เอกสารนี้เป็นสรุปล่าสุดเหนือบันทึกการทดลองเดินที่ล้มเหลวก่อนหน้า

ค่าที่อ่านได้โดยเครื่องอยู่ใน [contract.json](../characters/ddtank-lab-v1/contract.json) ส่วนรายการไฟล์และ SHA-256 อยู่ใน [baseline-lock.json](../characters/ddtank-lab-v1/baseline-lock.json) เก็บ PNG ของเรา พรอมต์ ต้นฉบับชุด โค้ดส่งออก เว็บ และ Godot adapters ไว้ด้วย รวมประมาณ 8 MB พร้อมภาพ guide ที่อนุญาตให้ใช้ฟรี ไม่รวมภาพ/atlas/SWF เชิงพาณิชย์ของ DDTank

## 1. โครงและการแบ่งชิ้นส่วน

ใช้หัวมาตรฐานว่างหนึ่งหัวต่อ family ไม่มีตา คิ้ว ปาก หรือผมอยู่ในหัว พิกัดและสัดส่วนของทุกชิ้นต้องเข้ากับหัวนี้ เสื้อผ้ามีร่างกายครบพร้อมคอ เสื้อ กางเกง/กระโปรง มือ ขา และรองเท้า การเปลี่ยนของเปลี่ยนภาพในช่องเดิม ไม่เปลี่ยนขนาดโครงหัวหรือหาจุดพอดีใหม่ตามแต่ละไอเท็ม

| ช่อง DDTank | ความหมาย | งานที่ใช้งานจริงตอนล็อก |
|---|---|---|
| `base_head` | โครงหัวว่างของเรา | หัว 3/4 เดิมหนึ่งหัว ใช้ร่วมทุกชุด/เฟรม |
| `hair` | ทรงผม | น้ำตาล + ฟ้าจากคู่ภาพใหม่; A สำหรับใต้หมวก / B ปกติ |
| `face` | ชุดดวงตา **รวมตา คิ้ว ปาก** | อำพันยิ้ม + เขียวมุ่งมั่น; มีการกระพริบ |
| `eff` | ชุดใบหน้า/รายละเอียดบนหัวเดิม | รอยแผล / แก้มแดงและกระ / ไม่ใส่; รอยสักและตุ้มหูเป็นชนิดที่จะเพิ่มภายหลัง |
| `head` | หมวก | หมวกนักเดินทางหนึ่งใบ / ไม่ใส่ |
| `cloth` | เสื้อผ้ารวมร่างกาย คอ และรองเท้า | นักเดินทาง + อัศวิน; แต่ละชุดมีภาพยืนและเดิน 8 เฟรม |
| `glass` | แว่นตา | renderer ชิ้นส่วนเดิมรองรับ; **ยังไม่มีแว่นของเราใน catalog ใหม่** |
| `wing` | ปีกหลังตัว | แลปเดิมแปลงและใช้ SWF/atlas ได้ 128 คู่; **ยังไม่มีช่องปีกใน UI ตัวละครใหม่** |
| `suits` | ชุดเต็มตัว/มาสคอตที่แทนตัวปกติ | compositor เดิมมี replacement mode; **ยังไม่มีชุด/pose family ของเรา** |
| `arm` | อาวุธ | ฝั่งเทียบใช้ข้อมูลอาวุธเดิมเพื่อคำนวณออร่า; **ยังไม่มีการผูกอาวุธยิง/ดาบกับท่าเดินใหม่** |

ผมปัดข้างฟ้าและผมหยักศกเงินที่เจ้าของสั่งลบไม่อยู่ใน catalog นี้ เก็บประวัติการทดลองไว้ในรีโปเดิมได้ แต่ห้ามนำกลับเข้า catalog หรือใช้เป็น template ที่ผ่านแล้ว

## 3. วิธีสร้างภาพ

**ผม:** สร้างสองภาพตามลำดับ (1) หัวมาตรฐานว่างพร้อมทรงผมใหม่ ไม่มีตา/คิ้ว/ปาก (2) ภาพเฉพาะผมพื้นโปร่งใสที่ตรงกับภาพแรก ใช้ ImageGen จากภาพแรก เก็บ raw outputs และ prompt ทั้งสอง ภาพหัว+ผมใช้ดูแบบ/ไอคอน ส่วนชั้นที่ประกอบจริงต้องเป็นผมล้วนเท่านั้น หัวในภาพที่สร้างใหม่ไม่แทนหัวมาตรฐาน ห้ามเจาะรูผิว/หูด้วยมือหรือตัดผมจากภาพมีใบหน้าเพื่อซ่อนความคลาดเคลื่อน คู่ผมฟ้าของจริงถูกเก็บไว้ใน [hair-pair-v1](../prototype/rpgjs-v5-adventurer-v0.2/assets/ddtank40-three-quarter-v1/hair-pair-v1/)

**ดวงตาและใบหน้า:** ชุดดวงตามีตา คิ้ว ปาก และต้องมาจาก source ไม่มีผมทับบริเวณเหล่านี้ ส่วน `eff` เป็นภาพรายละเอียดบนโครงเดิม ไม่เปลี่ยนรูปกะโหลก ทุกชิ้นต้องดูสะอาดแม้ถอดผมทั้งหมด

**เสื้อผ้า:** สร้าง headless dressed body ตั้งแต่แรก คอมน เสื้อปก/ผ้าพันคอครบ และคอยื่นเข้าไปซ้อนหลังคางโค้ง ห้ามสร้างรูปมีหัวแล้วตัดเป็นเส้นตรงเพื่อทำชั้นเสื้อ ชิ้นส่วนห้ามมีขอบคางหรือขอบใบหน้าค้างอยู่ ตรวจ source เดี่ยวและภาพประกอบจริงก่อนประกาศผ่าน

**ท่าเดินของแต่ละชุด:** ใช้ pose guide จาก Ginzii ที่เจ้าของเลือก ให้ AI วาดร่างแต่งชุดไม่มีหัวตาม 8 ท่าเดิม ชุดต่างกันต้องรักษามุมกล้องและท่าแต่ละเฟรม ตรวจขาซ้าย/ขวาสลับ stance/swing และแขน counter-swing จากภาพ ไม่แก้การเดินด้วยการบิดเข่าของภาพยืน

พรอมต์สองชุดและ clean headless masters อยู่ใน `characters/ddtank-lab-v1/web/authoring/` และ `generation-prompts.json` การตรวจตัวเลขไม่รับรองภาพข้อต่อหรือก้าวขา การสร้างไอเท็มต่อไปต้องเทียบ template และชุดที่ล็อกทุกเฟรมด้วยตาอีกครั้ง

## 4. การประกอบและสถานะ

ลำดับชั้นของตัวเรา: **cloth → base_head → face → eff → hair → head** จึงให้คอเสื้ออยู่หลังใบหน้า นี่เป็นลำดับของ custom layers; ลำดับ DDTank ต้นฉบับยังแยกเก็บไว้ตามหลักฐาน หากเพิ่มแว่น ต้องกำหนด coverage/layer ให้ครบและบันทึกเวอร์ชันใหม่ ห้ามอ้างว่าช่องแว่นมีแล้วเพราะมีชื่อในเอกสาร

ไม่เลือกเสื้อ/ผม/ตาใช้ค่าเริ่มต้นนักเดินทาง/น้ำตาล/อำพันยิ้ม ส่วนใบหน้าและหมวกไม่เลือกหมายถึงไม่ใส่ สลับชุดหรือของไม่รีเซ็ตเฟรม/phase การเดิน เดโมใหม่มี 9 ไอเท็มในกระเป๋า จัดได้ **48 looks** และ **384 look×walk-frame combinations** ตัวเลขนี้นับชุดผสม ไม่ใช่ใบรับรองคุณภาพภาพของทุกชุด

กระเป๋าและคลังออร่าใช้ `stand_show.png`: ยืนนิ่งและกระพริบตา เดโมเดินใช้ `walk_downleft.png`: 8 เฟรม ระยะรอบฐาน 0.9 วินาที (112.5 ms/เฟรมที่ 1×) ค่าเริ่มต้นที่เปิดดู 0.75× จึงเป็น **150 ms/เฟรม, 1.2 วินาที/รอบ** ไม่ใช้ภาพ freeze จากกลางก้าวเดินเป็นภาพยืน

การกระพริบใช้เวลาจริงแยกจากการเดิน ลืมตา → ปิด 0.16 วินาที → ลืมตา เว้นแบบสุ่ม 2.4–4.8 วินาที รักษาคิ้วและปากของชุดที่เลือก โดยปะภาพตาปิดเฉพาะ ocular polygons ที่บันทึกไว้ ปัจจุบันใช้ source ตาปิดร่วมหนึ่งภาพ ยังไม่ใช่คลิปปิดตาเฉพาะสำหรับทุก eye set ในอนาคต

ไอคอนผม/ดวงตา/ใบหน้า/หมวก = หัวมาตรฐาน + ชิ้นส่วนนั้น ดวงตาหนึ่งแบบมีช่องเก็บของเดียวและโชว์ตาปกติเท่านั้น `ours_face_3` อยู่ใน `animation_faces`/`blink.closed_asset` และ **ห้ามขึ้นใน inventory**

## 5. ปีก ออร่า และพรีวิว

ปีกในแลปเดิมแปลงเป็น atlas พร้อม origin ภายใน SWF และ bounds รวมทุก state ใช้ wing clock แยกตาม FPS มี back/front layers; character origin คงเดิมระหว่างกระพือ คู่ 15107 เสียจึงไม่ใช้ บาง timeline เป็น sample loop ไม่ใช่การรัน ActionScript และไม่มีขนาดผืนภาพเดียวสำหรับปีกทุกแบบ ค่า Lab wing defaults: portrait (20,40), scale 1.5; battle (0,0), scale 1.0 ซึ่งเป็น adaptation ของแลป ไม่ใช่พิกัด Flash portrait เดิม (-1,2)

วงอาวุธหลังตัว; ออร่าหมวก/เสื้อหน้าตัว Nimbus = max(ขั้นหมวก,ขั้นเสื้อ)×100 + ขั้นอาวุธ กติกาเดิม: +0–4→0, +5–8→1, +9–11→2, +12→3, ≥15/Gold→5; +13/+14→0 ใน original ส่วน Lab เติมขั้น 4 ด้วยภาพขั้น 3 ปรับ hue/scale1.1 และต้องระบุว่าเป็น Lab ออร่าตัวแสดงเมื่อ Totem≥10 ค่าเทียบเริ่ม arm+9/cloth+12/Totem10/original ให้ Nimbus302

พิกัดออร่า portrait เดิมขยายจาก display ด้วย 250/120: วง `(47,65)` → `(97.9167,135.4167)` และพื้น `(45,126)` → `(93.75,262.5)` **หัวของเรา x125 จึงต้องเลื่อนชั้นตัวละครรวมปีก −27 px เทียบกับเอฟเฟกต์** หลังปรับหัวอยู่ x98 เทียบวง97.9167 และกลาง support feet นักเดินทาง93.5/อัศวิน94 เทียบพื้น93.75 ต่างไม่เกิน0.5 px

ค่าตรงกลางออร่าเป็นค่าภายใน composite; x244 เป็นค่าจัดทั้ง composite ในช่องกระเป๋า ห้ามใช้การเลื่อนทั้งภาพรวมเพื่อกลบความคลาดเคลื่อนตัวละครกับเอฟเฟกต์ การแก้ครั้งก่อนที่ย้ายทั้งกลุ่มไม่แก้ปัญหานี้ ค่าที่ล็อกใช้ทั้ง Bag, Aura Gallery และ portrait ของตัวเรา โดย compositor ต้นฉบับรักษาการประกอบเดิม

## 7. การล็อกและตรวจ

จากรีโป root:

```powershell
python characters/ddtank-lab-v1/tools/verify_standard.py --self-test
python characters/ddtank-lab-v1/tools/verify_standard.py --live-root D:/Codex/DDtank
```

ตัวตรวจใช้ Python stdlib ตรวจ SHA-256 ขนาด PNG source/code/registration/catalog ชิ้นส่วน runtime24PNG และไฟล์ snapshot70รายการ รวม60รายการเทียบ live lab พร้อมคู่ source ผมที่รีโปเก็บอยู่แล้ว ตรวจว่า inventoryไม่มีตาปิดและไอคอนหัวเป็น78×78 รายงานอยู่ใน [verification.json](../characters/ddtank-lab-v1/evidence/verification.json)

เว็บและ Godot เพิ่ม guard ตอนโหลด catalog/PNG เทียบ `character-standard-lock.json`; exporter ตรวจผล PNG และ catalog กับ lockก่อนแทนไฟล์เดิม ตัวเปิด `Compare Characters + Bag Aura.cmd` เรียกตัวตรวจ snapshot/live ก่อนเปิดด้วย โดยล็อก metadata/config ภายนอกเพิ่ม10ไฟล์ (equipment, actions, wings, auras, UI, settings และจุดเข้าแอป) เก็บเฉพาะ hash/path ในรีโป ใน Godot guard ใช้ assertions ของ debug lab; release build ต้องเพิ่ม release-grade error handlingก่อนใช้จริง ตรวจ Godot ด้วย `--modular-comparison-test` และ `--bag-smoke-test` แล้วดูภาพจริง

หากมีงานที่เจ้าของสั่งเปลี่ยน ให้สร้างเวอร์ชันใหม่พร้อมเหตุผล/ค่าที่เปลี่ยน/ภาพเทียบ/ผลตรวจ รักษา v1 สำหรับย้อนกลับ **ห้ามสร้าง lock ใหม่ทับเพื่อให้เช็คที่ล้มเหลวกลายเป็นผ่าน**

## 8. งานที่ยังไม่สำเร็จ

ตัวเราใช้งานจริงเฉพาะ family ชาย มุมซ้ายล่าง stand/walk ไม่ใช่ระบบกระดูกที่เล่นได้ทุกท่า ยังไม่มีอีก7ทิศ, familyหญิง, วิ่ง, ยิงปืน, ฟันดาบ, ชุดเต็มตัว/มาสคอต หรือแว่น/ปีกใน catalog ใหม่ ยังไม่ได้เชื่อมเข้าตัวเกมหลัก/RPGJS/Phaser และยังไม่มีหลักฐานผลิตได้หลายพันชุด การล็อกนี้เก็บผลที่ทำได้และข้อตกลงการสร้างต่อ ไม่เปลี่ยนสถานะดังกล่าวเป็นสำเร็จ
